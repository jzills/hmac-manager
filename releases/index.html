      Release notes

      What each release of HmacManager changed, newest first. The six artifacts release separately, so each has its own section and versions. Each version links to its GitHub release, which adds the list of merged changes. Earlier versions without a tag are listed on NuGet and npm.

      NuGet package

      v2.13.0

      Requests whose body arrives without a length now verify, and a policy that only looks shared gets a warning at startup.

      • Chunked bodies: A request with no Content-Length header, such as a chunked upload or HTTP/2 through a proxy, now verifies, and your endpoint still receives the body.
      • HTTP/2 headers: With EnableConsolidatedHeaders(), a request whose header names arrive in lowercase gets a verification result instead of a 500.
      • Unknown-length bodies when signing: An empty body from a stream of unknown length, such as a network stream, no longer gets a content hash the server can’t match.
      • A replay warning at startup: A policy on the Distributed nonce cache with only the in-process MemoryDistributedCache behind it logs event 1203 once, since a replay that reaches another instance is accepted.

      nuget/v2.13.0 on GitHub

      v2.12.0

      A nonce cache now needs only one method, and you can replace either built-in cache with your own.

      • One method to implement: A nonce cache implements TryAddAsync, which claims a nonce atomically; derive from the public NonceCache base to have the expiry handled for you.
      • Replace one cache: Call AddNonceCache to put your own cache behind Memory or Distributed and keep the built-in one behind the other.
      • Keys that carry over: A replacement cache can key its entries with NonceCache.CreateKey, so nonces recorded before the switch stay claimed.
      • Redis windows: A replay inside the window is refused when the distributed cache is Redis, which used to drop an entry with under a second left.

      After upgrading: If you implement INonceCache, implement TryAddAsync: SetAsync and ContainsAsync are obsolete and go in v3.0.

      nuget/v2.12.0 on GitHub

      v2.11.0

      Replay protection is tighter: a nonce now lasts as long as its request, and a forged request can’t use one up.

      • Nonces for the whole window: The built-in caches keep each nonce until the request expires under its policy’s max age, not for a fixed 30 seconds.
      • Signature first: Verification checks the signature before it touches the nonce cache, so a forged request can’t claim a genuine request’s nonce.
      • Atomic memory cache: Two concurrent requests with the same nonce can no longer both pass the in-memory cache.
      • Clean failures: Malformed or non-Base64 headers and an unknown policy now fail authentication instead of returning a 500.
      • Custom caches: A custom nonce cache receives the policy’s max age through TryAddAsync.

      nuget/v2.11.0 on GitHub

      v2.10.0

      Three fixes that make a request signed in .NET verify everywhere else.

      • Internationalized hosts: A host such as bücher.example is signed in its punycode form, which is what travels in the Host header and what the npm client signs.
      • Padded header values: Scheme header values are trimmed before they are signed.
      • Empty bodies: A request with an empty StringContent body no longer adds a content hash that no verifier reproduces.

      After upgrading: If you sign requests to an internationalized host, upgrade the signer and the verifier together: the signature for those requests changes.

      nuget/v2.10.0 on GitHub

      v2.9.0

      A scheme name that doesn’t exist no longer signs requests silently without it.

      • Unknown schemes: Asking IHmacManagerFactory for a policy with a scheme it doesn’t have, as in Create("MyPolicy", "Typo"), now returns null instead of a manager that signs without the scheme.

      nuget/v2.9.0 on GitHub

      v2.8.0

      The library now explains itself in your logs.

      • Why a request failed: Every rejection writes a structured log entry that says which check failed, such as an expired request, a replayed nonce or a signature mismatch.
      • Stable event ids: Each message has an id you can alert on, listed on the log events page.
      • Loggers are optional: Every public type keeps its existing constructor, and dependency injection supplies a logger without any change to your code.

      nuget/v2.8.0 on GitHub

      v2.7.0

      Policies loaded from configuration now follow it while your app runs, and a request dated in the future is refused. These notes cover everything since v2.5.0, including v2.5.1 and v2.6.0, which had no tag.

      • Policies that reload: When you pass an IConfigurationSection to AddHmacManager, policies are added, replaced and removed as the configuration changes, with no restart.
      • No future dates: A request whose date is later than the server’s clock no longer verifies.
      • Absolute URIs: Signing outside the HttpClient handler requires a request with an absolute URI.
      • .NET 10: The package targets net8.0 and net10.0.

      nuget/v2.7.0 on GitHub

      v2.5.0

      Policies can now be built per request, the headers lose their X- prefix, and events run asynchronously.

      • Scoped policies: Call EnableScopedPolicies() to build the IHmacPolicyCollection per request from the IServiceProvider, for policies that live in a database.
      • One header: The EnableConsolidatedHeaders() option combines the generated headers into a single Base64-encoded header.
      • Earlier errors: Signing and verification throw specific exceptions, such as HmacPolicyNotFoundException, as soon as something is wrong.
      • Your own signing content in the client: The npm client supports user-defined signing content too.

      Breaking: If you handle HmacEvents, make each handler asynchronous. If a signer or verifier runs an earlier version, upgrade both together, since the header names changed.

      v2.5.0 on GitHub

      v2.4.5

      A patch for signed requests whose body was left out of the hash.

      • POST bodies: A body sent with chunked transfer encoding, which PostAsJsonAsync uses by default, is now included in the content hash.
      • Bodies in the npm client: The client reads a clone of the request, so hashing the body no longer consumes it.
      • One dependency: The package now depends only on System.Runtime.Caching.

      v2.4.5 on GitHub

      v2.4.0

      The npm client arrives, and the library now writes the request date the way the client does.

      • The npm client: The hmac-manager package, v1.0.0, signs requests from a browser or Node.
      • Dates in milliseconds: The date requested is now Unix time in milliseconds, so the library and the client agree on it.

      Breaking: If a signer or a verifier runs an earlier version, upgrade both together: requests signed with the old date format no longer verify.

      v2.4.0 on GitHub

      v2.3.0

      You can now check the keys on a request yourself and decide exactly what gets signed.

      • A key check of your own: The new OnValidateKeys event runs before verification, so you can refuse a request by its public key.
      • Your own signing content: A policy can build its own signing content with UseSigningContentBuilder, which gives you full control over what is signed and verified.
      • Events with configuration: An AddHmac overload takes an IConfigurationSection and an HmacEvents together.

      v2.3.0 on GitHub

      v2.2.0

      Policies can now come from configuration and change while your app runs.

      • Policies from configuration: New AddHmacManager and AddHmac overloads take an IConfigurationSection, so you can define policies in appsettings.json or any other configuration provider.
      • Dynamic policies: The IHmacPolicyCollection lets you add and remove policies at runtime.
      • Policies as JSON: An HmacPolicy can be serialized and deserialized with JsonSerializer.
      • IntelliSense: The XML documentation now renders in your editor.

      v2.2.0 on GitHub

      v2.1.0

      Your authentication events can now see the outcome of each request, and the package registers a nonce cache for you when you haven’t.

      • Results in events: The HmacEvents handlers receive the HmacResult, so you can see whether a request passed and which policy and scheme it used.
      • Default caches: When nothing else is registered, AddHmacManager registers the default nonce caches itself.

      v2.1.0 on GitHub

      npm client

      v2.9.0

      A nonce store now needs only one method, and verification reports a replay as a replay.

      • One method to implement: A NonceStore implements tryAdd(nonce, dateRequested, maxAgeInSeconds), which receives the policy’s max age.
      • The right reason: A replay whose store round trip crosses the end of its window is reported as a replay, not an expiry.

      After upgrading: If you wrote your own NonceStore, implement tryAdd with its new third argument: has and set are deprecated.

      npm/v2.9.0 on GitHub

      v2.8.0

      Verification in the client is now as strict about nonces as the library.

      • Signature first: The verify method checks the signature before it touches the nonce store, so a forged request can’t use up a genuine request’s nonce.
      • Atomic stores: A NonceStore can implement tryAdd, which claims a nonce in one step, so two concurrent requests with the same nonce can’t both pass.

      npm/v2.8.0 on GitHub

      v2.7.0

      A Node service can now verify signed requests itself, not only send them.

      • Verification: The verify method checks a signed request the same way VerifyAsync does in .NET, and reports each rejection reason separately instead of throwing.
      • Replay protection: An in-process NonceStore refuses a nonce it has already seen, and you can supply your own store.
      • Uppercase nonces: A nonce sent in uppercase by another signer now verifies, since the client compares it in lowercase as .NET does.

      npm/v2.7.0 on GitHub

      v2.6.0

      The client now refuses a scheme that doesn’t exist, as the library does. These notes cover everything since v2.5.0, including v2.5.1 and v2.5.3, which had no tag.

      • Unknown schemes: Creating a manager with a scheme the policy doesn’t have now returns null instead of a manager that signs without it.
      • Blank schemes: An empty or whitespace scheme name counts as no scheme, as in .NET.
      • Types: The published TypeScript declarations match the exports.

      npm/v2.6.0 on GitHub

      v0.1.0

      ext-authz service

      v0.5.1

      A request whose body arrives without a Content-Length header now verifies.

      • Chunked bodies: A chunked body with no length is read in full before it is verified, instead of being measured as empty and denied.
      • The library inside: It carries the NuGet package v2.13.0, which also verifies HTTP/2 requests with lowercase header names.

      service/v0.5.1 on GitHub

      v0.5.0

      With a Redis connection, the service now claims each nonce atomically, so two replicas can’t both accept the same request.

      • Atomic claims: When ConnectionStrings:Redis is set, nonces go through the Redis package v1.0.0, one SET NX per claim.
      • Rolling upgrades: The keys are the ones earlier versions wrote, so nonces claimed before the upgrade stay claimed.
      • Fails closed: When Redis can’t be reached, the request is denied rather than allowed without replay protection.

      service/v0.5.0 on GitHub

      v0.4.2

      Carries the NuGet package v2.11.0, which tightens replay protection.

      • Nonces for the whole window: Each nonce is kept until its request expires under the policy’s max age.
      • Signature first: A forged request can no longer claim a genuine request’s nonce.
      • Clean failures: Malformed headers are denied instead of failing the check.

      service/v0.4.2 on GitHub

      v0.4.1

      Carries the NuGet package v2.10.0: requests to an internationalized host, requests with padded scheme header values and requests with an empty body now verify as their signer intended.

      After upgrading: If your clients sign requests to an internationalized host, upgrade them to the NuGet package v2.10.0 or the npm client v2.7.0 at the same time.

      service/v0.4.1 on GitHub

      v0.4.0

      Carries the NuGet package v2.9.0, so a request that names a scheme the policy doesn’t have is refused instead of being verified without it.

      service/v0.4.0 on GitHub

      v0.3.0

      Every denial now says why in the service’s logs.

      • Reasons for a 403: Envoy only sees a 403, but the service logs which check failed, such as an expired request, a replayed nonce or a signature mismatch, with a stable event id.

      service/v0.3.0 on GitHub

      v0.2.0

      Policy and key changes now take effect without restarting the service.

      • Live policies: The service reloads its policies when their configuration changes, which is how the operator’s HmacPolicy resources reach it.
      • Keys from a Secret volume: Private keys are read from mounted files, so a rotated key takes effect on the running pods.

      service/v0.2.0 on GitHub

      v0.1.0

      Replay protection now holds across replicas when the service has a Redis connection.

      • Shared nonces: With ConnectionStrings:Redis set, the service keeps its nonces in Redis, so a replay that reaches another replica is refused. The Helm chart v0.1.0 sets it for you.

      service/v0.1.0 on GitHub

      v0.0.1

      The first pre-release of the ext-authz service, which verifies HMAC-signed requests for a whole Istio ambient mesh, with no change to your applications.

      • One check for every request: The Istio waypoint calls the service before forwarding a request, and the service answers with HmacManager’s verification.
      • The image: It publishes zills/hmac-manager:0.0.1 to Docker Hub.

      Redis package

      v1.0.0

      The first release of HmacManager.StackExchangeRedis, a nonce cache that claims each nonce in Redis atomically, so replay protection holds across every instance of your app.

      • One call: Call AddStackExchangeRedisNonceCache to put the Redis cache behind the Distributed cache type, with no change to your policies.
      • Atomic claims: Each claim is one SET NX, so two instances can’t both accept the same nonce.
      • Fails closed: When Redis can’t be reached, the request fails rather than being accepted without replay protection, and concurrent requests share one connection attempt.
      • Keys that carry over: Set InstanceName to match the RedisCache you used before, and nonces it recorded stay claimed.

      redis/v1.0.0 on GitHub

      HMAC request authentication, in your app or in your mesh. Sign and verify requests against named policies, with replay protection built in.
